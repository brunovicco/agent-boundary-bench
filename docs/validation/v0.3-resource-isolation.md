## Bounded observations

The clearest constrained treatment occurred in the A2A, 25,000-CPU-iteration, 8 MiB condition:

| Profile | n | P50 | P95 | Specialist throttled time |
|---|---:|---:|---:|---:|
| generous | 5 | 104.917 ms | 122.530 ms | 0 s |
| constrained | 5 | 1,053.340 ms | 1,411.018 ms | 2.787763 s |

The matched local condition retained the same one-CPU harness cgroup in both profiles and
observed P50 104.953 ms (generous) versus 101.180 ms (constrained). Across all eight remote
rounds per profile, sampled specialist throttled-time deltas summed to 0.065566 seconds for
generous and 5.360728 seconds for constrained. This aggregation describes these non-overlapping
smoke windows only.

These observations show that the configured remote cgroup encountered quota throttling and that
the treatment path is measurable. They do not prove a portable 10× penalty, isolate transport as
the cause or establish a general HTTP/A2A ranking. Each cell has one round and five requests;
round order, host activity, Docker scheduling and cumulative persistent-container state remain
possible influences.

## Acceptance boundary

Implementation, native validation and both Docker smoke profiles are complete for this
milestone. Raw data are committed under `experiments/results/v030-resource-isolation-macos/` and
derived artifacts under `reports/v030-resource-isolation-macos/`.

Article-level resource/capacity claims still require the two 180-round repeated profiles,
calibrated arrival sweeps, no competing workloads and analysis across repetitions. Cross-host
network faults and fixed-total-architecture-budget treatments also remain future work. CI runs a
functional generous smoke but does not publish shared-runner timing as benchmark evidence.
