# v0.3 resource-isolation development validation — 2026-10-26

## Scope and status

This record covers implementation validation for the second `0.3.0.dev0` milestone, based on
merged main commit `74bf60fddfb4f8c6badabba6381184086e4e93e5`. It adds explicit CPU/memory
workloads, a Compose isolation topology, cgroup v2 observations, schema v4 and report/validation
support. It is not a v0.3 release or a record of completed Docker resource-isolation campaigns.

## Not executed here

This isolated Linux workspace has no Docker binary or daemon. Therefore the following were not
executed here:

- merged Compose semantic validation with `docker compose config`;
- generous/constrained container smoke campaigns;
- verification that Docker Desktop exposes the requested cgroup v2 quotas on the user's macOS
  host;
- `scripts/capture_container_environment.py` against the user's Docker engine;
- `scripts/validate_isolation_results.py` against real container campaign output;
- the two 180-round full profiles.

The Compose CI job now performs the 12-round generous functional smoke with zero sampling loss
allowed. It also rejects absent image provenance, incomplete output, non-v2 cgroups and observed
limits that differ from the declared profile. Constrained profiles may declare a bounded loss
rate while retaining the exact counts and at least two valid observations per role. CI timings
are not uploaded or described as benchmark results.

## Acceptance boundary

Implementation and native validation are complete for this milestone. Performance conclusions
remain pending until both macOS Docker smoke profiles pass and their raw manifests/resources are
reviewed. The smoke validates wiring only. Article-level resource claims require the repeated
full profiles, no competing workloads, clean commit provenance and explicit review of scheduler
lag, drops, errors, throttling and memory events.
