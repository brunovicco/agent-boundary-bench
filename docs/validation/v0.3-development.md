# v0.3 development validation — 2026-10-26

## Scope and status

This record covers the first `0.3.0.dev0` milestone on branch `feat/v0.3.0`. It validates
controlled application-layer failures, bounded retries, worker-local idempotency and service
admission/backpressure behavior. It is not a v0.3 release record, a sustained-capacity campaign
or evidence for infrastructure failure containment.

The source tree was intentionally dirty while this development validation ran. The functional
smoke data were written to an ephemeral directory and are not committed benchmark evidence.
The released v0.2 datasets and validation records were not relabeled or replaced.

## Functional recovery smoke

One measured execution per delegation boundary used the 1 KiB fixture, zero synthetic wait,
`after-commit`, two maximum attempts and worker-local idempotency. Each execution fans out to the
three specialists.

| Scenario | Offered / succeeded | Attempts | Retries | Kernel executions | Idempotency hits | Injected failures | Remote calls |
|---|---:|---:|---:|---:|---:|---:|---:|
| local | 1 / 1 | 6 | 3 | 3 | 3 | 3 | 0 |
| HTTP | 1 / 1 | 6 | 3 | 3 | 3 | 3 | 6 |
| A2A | 1 / 1 | 6 | 3 | 3 | 3 | 3 | 6 |

All three results matched the deterministic business oracle. The first attempt for each
specialist executed the kernel and then returned the declared transient failure. The retry reused
the stable delegation ID and returned the cached result without duplicate kernel work. HTTP used
headers and A2A used the official public `Message.metadata` field for this application metadata.

These are three functional samples from a dirty checkout with generator and system under test on
the same host. Their latency values must not be reported as portable benchmark results. Raw smoke
files were deliberately not added to `experiments/results/`.

Two additional dirty-checkout diagnostics validated the factorized campaign definitions after a
macOS run exposed a race between the A2A SDK transport timeout and the application attempt
deadline:

| Campaign | Rounds | Offered / succeeded | Errors | Timeouts | Drops |
|---|---:|---:|---:|---:|---:|
| Resilience smoke | 24 / 24 | 72 / 72 | 0 | 0 | 0 |
| Timeout smoke | 3 / 3 | 3 / 3 | 0 | 0 | 0 |

The general resilience matrix now keeps a one-second attempt deadline. The timeout treatment is a
separate matrix with a one-second attempt deadline, 2,000 ms injected delay and 1,500 ms backoff.
This prevents ordinary loopback jitter from being mislabeled as an injected timeout. These smoke
files are ephemeral functional evidence, not committed performance results.

## Validated failure semantics

Automated tests additionally cover:

- deterministic fail-before-execution, delayed first attempt and fail-after-commit treatments;
- per-attempt timeout distinct from the overall supervisor deadline;
- retry exhaustion with completed-attempt metrics retained in the failure sample;
- recovery with and without idempotency, exposing duplicate kernel work explicitly;
- permanent conflict when one idempotency key is reused with a different canonical task hash;
- bounded cache capacity and TTL configuration;
- immediate overload rejection and bounded queue timeout;
- expected treatment failures during warmup recorded as `warmup_failed`;
- unexpected transport/setup failures still aborting warmup;
- schema-v3 integrity, report generation and compatibility with v1/v2 result files.

## Not validated in this record

- Docker Compose for the initial patch passed on the user's macOS host: the image built, all
  HTTP/A2A/MCP services became healthy and the `verify` service confirmed functional equivalence.
  The incremental timeout correction still requires one macOS Compose rerun.
- The 1,920-round resilience, 120-round timeout and 270-round backpressure matrices.
- Sustained saturation with an external isolated load generator.
- Container CPU/memory interference and resource-isolation treatments.
- Process, proxy, packet, machine or cross-host failure injection.
- Durable cross-worker idempotency or A2A durable task recovery/polling.
- Collector/exporter failure matrices and lost-span accounting.
